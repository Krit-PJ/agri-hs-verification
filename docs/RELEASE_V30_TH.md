# v3.0 — ฐานข้อมูลใหม่ และระบบผู้ดูแลเดียวกับ Agri-Risk Map Burning

รุ่นนี้แทนที่ระบบรุ่น 2.x ทั้งหมด (โค้ดและเอกสารรุ่นเก่าอยู่ในประวัติ git และ `docs/archive-v2/`)

## สิ่งที่เปลี่ยน

* **ข้อมูล HS**: อ่านจากแท็บ `HS_<รหัสจังหวัด>` ของฐานข้อมูล Agri-Risk Map Burning โดยตรง (ไม่นำเข้าไฟล์ซ้ำในระบบนี้อีก) — เมื่อผู้ดูแลจังหวัดนำเข้า HS ในระบบแผนที่ ระบบตรวจสอบเห็นข้อมูลชุดเดียวกัน
* **ฐานข้อมูลใหม่**: Google Sheet `Thailand HS Verification - Database` + โฟลเดอร์ภาพ ในโฟลเดอร์ Drive `5. Thailand HS Verification`
* **บทบาท** (เข้าสู่ระบบแบบเดียวกับ Agri-Risk Map Burning)
  * Super Admin — ชื่อผู้ใช้ + รหัสผ่าน จัดการได้ทั้งระบบ
  * Mini Super Admin — เบอร์โทร อนุมัติ/อนุญาตเจ้าหน้าที่ในจังหวัด และบันทึก แก้ไข เพิ่ม ลบ ข้อมูลระดับจังหวัด
  * Admin — เบอร์โทร ผู้บันทึกข้อมูลผลตรวจ HS ในจังหวัด
* **บันทึกการใช้งาน**: ชีต `AuditLog` + `LoginAttempts` และหน้าดูบันทึกพร้อมตัวกรอง สรุปรายบุคคล ส่งออก CSV
* **ขออนุญาตใช้งาน**: ผู้ใช้ยื่นคำขอจากหน้าเว็บ ผู้ดูแลจังหวัดอนุมัติได้ทันที
* หน้าเว็บคงโครงและรูปแบบเดิม (ส่วนหัว เมนู แผนที่ รายการ ตัวกรอง สรุปผล ฟอร์มบันทึกผล ภาพหลักฐาน งานค้างเมื่อออฟไลน์ รายงานพิมพ์)

## ยกเลิกจากรุ่น 2.x

* การนำเข้าไฟล์ HS ในระบบนี้ (นำเข้าที่ระบบ Agri-Risk Map Burning แทน)
* บัญชีชื่อผู้ใช้/รหัสผ่านของ Admin รายจังหวัด และบัญชีผู้ตรวจแบบ token — ใช้เบอร์โทรที่ได้รับอนุญาตแทน
* โหมดทดสอบในเบราว์เซอร์ (ใช้ `node scripts/dev-server.js` ที่รันโค้ด Backend จริงกับฐานข้อมูลจำลองแทน)

## ข้อมูลรุ่นเก่า

ผลตรวจในฐานข้อมูลรุ่น 2.x ไม่ถูกย้ายอัตโนมัติ เพราะใช้รหัสจุดและโครงสร้างต่างกัน หากต้องการย้าย ให้ส่งออก CSV จากระบบเดิมแล้วจับคู่ hotspotId กับแท็บ HS_xx ก่อนนำเข้าชีต `Verifications`

## การทดสอบ

`npm test` 24 รายการ: Backend รันโค้ด `apps-script/*.gs` จริงกับบริการ Google จำลอง (สิทธิ์ทุกบทบาท ขอบเขตจังหวัด การระงับบัญชี ภาพ การบันทึกการใช้งาน การกันสูตรแฝง) และฟังก์ชันหน้าเว็บ
