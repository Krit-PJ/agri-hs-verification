# รุ่น 2.3 — เบอร์โทรสำหรับผู้บันทึก และ Header ใหม่

## สิ่งที่ส่งมอบ
- ผู้บันทึกข้อมูลลงทะเบียนโดยไม่มีช่องรหัสผ่าน/ยืนยันรหัสผ่าน แล้วรอผู้ดูแลอนุมัติ
- เข้าสู่ระบบด้วยเบอร์มือถือไทย10หลักผ่าน loginPhone เฉพาะบัญชี authMethod=phone_only ที่อนุมัติและ active แล้ว
- Admin และ Super Admin ยังคงใช้ชื่อผู้ใช้/รหัสผ่านเดิม บัญชีดังกล่าวใช้ loginPhone ไม่ได้
- เพิ่มตัวอย่างตำแหน่ง “ผู้ใหญ่บ้านหมู่ที่ 1 ตำบลวังแขม” และรายการกำนัน ผู้ใหญ่บ้าน ผู้ช่วยผู้ใหญ่บ้าน อกม. ช่องสังกัด/บทบาทแยกจากสิทธิ์ระบบ ผู้สมัครเลือกสิทธิ์ Admin เองไม่ได้
- บทบาทชุมชนยังต้องระบุจังหวัดและอำเภอ; profile ฝั่งเซิร์ฟเวอร์ยังจำกัดขอบเขต district/province โดยบันทึกชื่อบทบาทไว้ใน agency ไม่ให้สิทธิ์กว้างขึ้น
- ย้ายจังหวัดและบัญชีมาใต้ Hero ซ่อนรายละเอียดความครอบคลุมในส่วนเปิดอ่าน และย่อข้อความเหนือแผนที่ บนมือถือใช้เมนูเลื่อนแนวนอน

## ข้อจำกัดที่ผู้ใช้ยืนยันรับทราบ
การรู้หมายเลขโทรศัพท์ของผู้ได้รับอนุมัติอาจทำให้บุคคลอื่นสวมบัญชีได้ การแจกเว็บไซต์เฉพาะกลุ่ม การอนุมัติ และการจำกัดความถี่ไม่ยืนยันเจ้าของเบอร์ ไม่มี OTP ระบบจึงเป็นการระบุบัญชีด้วยเบอร์โทรตามทางเลือกที่ผู้ใช้ยืนยัน ไม่ใช่การพิสูจน์เจ้าของหมายเลข

เซสชันมีวันหมดอายุ CSRF และการตรวจสิทธิ์จังหวัด/อำเภอเช่นเดิม loginPhone มีข้อจำกัดความถี่ต่อเบอร์และรวมทุกคำขอแบบ best effort บน Apps Script Cache ไม่ใช่ระบบป้องกันการโจมตีระดับบริการเฉพาะทาง

## สถานะระบบจริง
ติดตั้งและเผยแพร่ Apps Script รุ่น2.3แล้ว เป็น deployment เวอร์ชัน5 วันที่18ตุลาคม2569 เวลา08:10 ใช้ URL /exec เดิม หลังผู้ใช้ยืนยันเผยแพร่ ตรวจ API จริงได้ configured=true และ authMethod=phone_only ตรวจ previewRegisteredPhoneMigration พบ eligible=0 converted=0 skipped=0 จึงไม่แปลงบัญชีเดิม ส่วน Frontend รุ่น2.3ยังไม่เผยแพร่ขึ้น GitHub Pages
Frontend ตรวจ capability จาก getRegistrationPolicy.authMethod ต้องเป็น phone_only ก่อนเปิดรับคำขอแบบไม่มีรหัสผ่าน จึงไม่ส่งคำขอที่ไม่เข้ากับ Backend เก่า

## ติดตั้ง Apps Script
1. สำรองโค้ดและข้อมูลก่อนเปลี่ยนรุ่น
2. ใช้ docs/AppsScript-v23-All.gs แทนโค้ดรวมเดิม หรืออัปเดตไฟล์ apps-script/ ทุกไฟล์ ห้ามใส่แบบรวมและแบบแยกพร้อมกัน
3. บันทึกโค้ด ไม่ต้องสร้างชีตใหม่และไม่ต้องเรียก setupInitialLoginAccounts ซ้ำ คง Script Properties ของฐานข้อมูล Drive และ PDPA เดิมไว้
4. หากมีผู้สมัคร/ผู้บันทึกเดิมที่ใช้รหัสผ่าน เรียก previewRegisteredPhoneMigration เพื่อตรวจนับก่อน ใช้ applyRegisteredPhoneMigration เฉพาะเมื่อผู้ดูแลต้องการแปลงบัญชีเหล่านั้นจริง เครื่องมือแปลงเฉพาะ inspector ที่มีทะเบียนและขอบเขตตรงกัน ไม่เปลี่ยนการอนุมัติและไม่เปลี่ยน Admin/Super Admin แถวที่ไม่ตรงจะข้ามให้ตรวจสอบเอง เซสชันบัญชีที่แปลงจะหมดสิทธิ์และต้องเข้าใหม่
5. เผยแพร่เวอร์ชันใหม่บน deployment เดิมเพื่อใช้ URL /exec เดิม
6. ตรวจ getRegistrationPolicy ให้ configured=true และ authMethod=phone_only จากนั้นทดสอบสมัครในฐานทดสอบ → รออนุมัติ → เบอร์โทรเข้าได้ → ดูและบันทึกเฉพาะพื้นที่ → ออกจากระบบ
7. ตรวจว่าบัญชีรออนุมัติ ปฏิเสธ ปิดใช้งาน และ Admin/Super Admin เข้าด้วย loginPhone ไม่ได้

## Frontend
ใช้ index.html และไฟล์ JS/CSS ทั้งชุด โดยคง site-config.js เป็น URL API ของจริง deploy ด้วย GitHub Pages workflow เดิม ไฟล์ demo.html ใช้ phone-demo-config.js และ phone-demo.js เฉพาะตัวอย่างใน localhost ไม่มีการส่ง API หรือให้สิทธิ์บันทึกจริง ไม่ใช้ demo.html แทนหน้าใช้งานจริง

## การตรวจสอบ
ชุดทดสอบ135รายการผ่าน ตรวจ syntax JavaScript และ Apps Script และตรวจหน้าจอมือถือ390px ไม่มี page overflow การทดสอบบัญชีจริงบน Google แบบครบวงจรยังไม่ได้ดำเนินการ ไม่มีการสร้างผู้ใช้ทดสอบในฐานข้อมูลจริง
