# ฐาน HS ร่วมกันระหว่างแผนที่ความเสี่ยงและการตรวจสอบ

`data/risk-datasets.json` อ้างไฟล์ GeoJSON จากแผนที่ความเสี่ยงโดยตรง ไม่มีการสร้าง HS ID ใหม่ ปีล่าสุดเลือกจากปีชุดข้อมูลสูงสุด (2569) ไม่ใช้ปีปฏิทินปัจจุบัน ชุดปี 2569 มี 593 จุด วันที่ตรวจพบอาจอยู่ปีปฏิทินอื่นได้ จึงเก็บ `datasetYearBe` แยกจาก `calendarYearBe`.

เมื่อปรับปรุงไฟล์ต้นทาง ต้องเปลี่ยนไฟล์ `risk/data/hotspot/hotspot_YYYY.geojson` และทะเบียนปีด้วย หรือใช้ Super Admin นำเข้าฐานร่วม การรีเฟรชโหลดผ่าน `cache: no-store` เพื่อดึงไฟล์ใหม่จากเซิร์ฟเวอร์ แต่ไม่สามารถสร้างข้อมูลดาวเทียมใหม่เองได้

เมื่อเชื่อม Apps Script ทั้งสองหน้าจะอ่าน HS_Base เดียวกันจาก `bootstrap` พร้อมรหัสเซสชัน ปีที่ไม่มีในฐานสดแสดงว่าง ไม่แทนด้วยข้อมูลเก่า หาก API ล้มเหลว แสดงข้อความผิดพลาดแทนการสลับข้อมูลโดยไม่แจ้ง ในโหมดทดลอง การนำเข้าเก็บ `hsverify.sharedDataset` ใน browser storage ร่วม origin เดียวกัน; มีผลเฉพาะเครื่องและ browser นี้ หลัง deploy จริงให้ใช้ฐาน Sheets และนำเข้าผ่าน API

## ไฟล์นำเข้า

รองรับ .csv, .xlsx, .xls, .json, .geojson ไม่เกิน 10 MB และ 5,000 แถวต่อครั้ง ต้องมี HS ID, วันที่, เวลา, latitude, longitude, จังหวัด, อำเภอ, ตำบล, LandType, PlantType; หมู่บ้านเว้นว่างได้ ตัวอ่านรองรับหัวตารางไทย และ aliases เช่น `hs_id`, `acq_date`, `Time`, `Province`, `Amphoe`, `Tambon`, `BaanN`.

Excel เลือก `hsAll` ก่อน `HS_Base` และ `hsPlant2026` ตามลำดับ หรือส่ง sheetName ที่ต้องการ Excel ใช้ SheetJS ที่หน้าเว็บโหลดและใช้วันที่แบบ Excel serial ได้ `hsPlant2026` ที่เป็น pivot/ยอดรวมไม่มีพิกัดและรหัสรายจุด จึงต้องใช้ชีตรายจุด `hsAll` ใน workbook เดียวกัน การใช้ตารางสรุปสร้างพิกัดจะทำให้จำนวนและตำแหน่งคลาดเคลื่อน ระบบปฏิเสธแทนการคาดเดา

QA รับเฉพาะจังหวัดกำแพงเพชร พื้นที่เกษตร พืช นาข้าว / อ้อย / เกษตรอื่นๆ / อื่นๆ ตัด ID ซ้ำและข้อมูลวันที่-เวลา-พิกัดซ้ำ รายงาน accepted / invalid / outOfScope / duplicates และตัวอย่างข้อผิดพลาด ตรวจ preview ก่อนยืนยันนำเข้า

`HSData.normalizeRows` ให้รูปแบบ canonical camelCase: hsId, acquiredAt (YYYY-MM-DD), time (HH:mm), latitude, longitude, province, district, tambon, village, landType, plantType, datasetYearBe, calendarYearBe, sourceSheet, status. `HSData.toRiskGeoJSON` เพิ่ม aliases ที่แผนที่ความเสี่ยงใช้ โดยรักษา ID และปีชุดข้อมูลเดิม

การชี้ Google Sheet URL เพียงอย่างเดียวไม่ทำให้ชีตส่วนตัวเปิดอ่านจาก static web ได้ ต้องให้ Apps Script ที่ deploy มีสิทธิ์เข้าถึงชีต และตั้งค่า Sheet ID/ชีตรายจุดด้วย Super Admin ไม่มีการใส่ credential ลง GitHub

## การตัดสินใจเพื่อให้ยอดตรงกัน
1. กำหนด HS ID จากต้นทางเป็น key และเก็บปีชุดข้อมูลแยกปีวันตรวจพบ ไม่สร้างจุดจาก Pivot
2. อ่าน GeoJSON เดิมผ่านทะเบียนปี และใช้ HS_Base เดียวกันเมื่อเชื่อม endpoint ข้อมูลตัวอย่างอ้างอิงถึง 26 สิงหาคม 2569 ไม่ใช่ข้อมูลดาวเทียมสด
3. ปุ่มอัปเดตโหลดปีล่าสุดที่มีในแหล่งข้อมูล การ sync ต้นทาง Google เป็นคำสั่ง Super Admin อีกขั้นหนึ่ง ไม่มีการดึงดาวเทียมใหม่เอง
4. ตั้งเงื่อนไขจังหวัด/พื้นที่/พืชเดียวกัน ตรวจ ID พิกัด วันเวลา และเทียบยอดก่อนแทนที่ฐาน
5. ใช้ server role และ token เดียวกันใน origin เดียวกัน ทั้งสองหน้าไม่คัดลอก credential ลง source; ต้องเปิดลิงก์ภายในแท็บเดียวกันเพื่อใช้ sessionStorage ผู้ตรวจที่ถูกจำกัดพื้นที่จะเห็นเฉพาะพื้นที่มีสิทธิ์
6. เมื่อเพิ่มปีใหม่ แผนที่ risk รับปีที่มีในทะเบียน/ฐานร่วมโดยอัตโนมัติ แต่สูตร/น้ำหนักความเสี่ยงเดิมยังไม่ได้ปรับตามปีใหม่ ต้องทบทวนโมเดลก่อนใช้จัดอันดับความเสี่ยงข้ามปี
7. การนำเข้าในรุ่นนี้แทนที่ฐาน HS ทั้งชุด ไม่รวมกับชุดเดิมโดยอัตโนมัติ ต้องเลือกชุดข้อมูลที่จะใช้อย่างชัดเจน ผลตรวจ/รูปเดิมยังเก็บในประวัติ แต่ HS ที่ไม่มีในฐานใหม่อาจปรากฏเป็น orphan ใน QA
8. หากใช้ฐานสดที่มีเฉพาะปีล่าสุด หน้าความเสี่ยงไม่ผสมข้อมูลปีก่อนจากไฟล์เก่าแบบเงียบ ๆ ปีที่ไม่มีจะว่าง ดังนั้นความเสี่ยงแบบถ่วงหลายปีไม่เทียบกับ baseline เดิมจนกว่าจะเติมประวัติครบ/ตรวจโมเดล
