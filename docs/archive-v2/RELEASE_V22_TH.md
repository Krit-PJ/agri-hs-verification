# รุ่น 2.2 — ลงทะเบียน สังกัด ปีงบประมาณ และภาพหลักฐาน

## สิ่งที่เปลี่ยน
- แก้ Hero เป็น “พื้นที่การเกษตรในจังหวัด…” ตามจังหวัดที่เลือก
- สมัครด้วยโทรศัพท์ (ชื่อผู้ใช้) ชื่อ ตำแหน่ง สังกัดระดับอำเภอ/จังหวัด จังหวัด อำเภอ และรหัสผ่านอย่างน้อย 10 ตัวอักษร รับทราบประกาศฉบับ 2026-10-v1 ครั้งเดียวตอนสมัคร
- สมัครแล้วเป็น pending บัญชี inactive ไม่มีสิทธิ์บันทึกทันที Admin อนุมัติเฉพาะจังหวัดตนเอง Super Admin อนุมัติทุกจังหวัด โทรศัพท์ไม่ผ่าน OTP จึงต้องตรวจสังกัดนอกระบบก่อนอนุมัติ
- สิทธิ์จังหวัดและอำเภอตรวจที่เซิร์ฟเวอร์ ไม่เชื่อค่าจากฟอร์ม ผู้ลงทะเบียนไม่เลือก role เอง บัญชี Admin/Super Admin เดิมยังอยู่
- User_Registration สร้างเพิ่มแบบไม่ล้าง HS หรือผลตรวจ ไม่มีรหัสผ่านในชีต รหัสผ่านเก็บแบบ salt/hash เดิม
- ปีงบประมาณใช้วันที่เกิด HS ตามเวลาไทย เริ่มตุลาคมถึงเดือนสิ้นสุดที่เลือก รวมทั้งเดือน ไม่เปลี่ยน dataset/season year เดิม ค่าเริ่มต้นปีงบประมาณ 2570 เริ่มตุลาคม 2569 และสิ้นสุดเดือนล่าสุดที่มีข้อมูลในปีนั้น ถ้าไม่มีแสดง 0 พร้อมคำอธิบาย เลือกปีเก่าได้
- รับต้นฉบับ JPEG/PNG/WebP ไม่เกิน30MiB อ่าน EXIF ก่อนย่อ JPEG ด้านยาวไม่เกิน1920px ลดคุณภาพ/มิติจนไม่เกิน1,000,000ไบต์ ไม่รับ HEIC ไม่เก็บต้นฉบับใน Drive
- เก็บ original SHA256 แยกจาก derivative hash และ metadata ต้นฉบับที่ผู้ใช้ส่งมา ไม่อ้างว่าเซิร์ฟเวอร์ตรวจต้นฉบับแล้ว EXIF แก้ไขได้และเป็นพิกัดกล้อง ต้องสอบทวนกับ HS
- เปิดภาพภายใต้ HS เฉพาะผลตรวจ verified และผู้มีสิทธิ์ ผ่าน API ไม่เปิด Drive public ภาพเก่าอ่านได้ไม่เกิน5MiB ภาพใหม่จำกัด1MB

## ติดตั้ง/อัปเกรด
1. สำรองฐานข้อมูล Google Sheets และ Script Properties ตามนโยบายหน่วยงาน
2. นำไฟล์ apps-script ทั้งหมดรวม RegistrationService.gs ขึ้นโครงการเดิม หรือใช้ docs/AppsScript-v22-All.gs แทนโค้ดรวมเดิมเพียงไฟล์เดียว ห้ามใส่ทั้งแบบแยกและแบบรวมพร้อมกันเพราะชื่อฟังก์ชันซ้ำ
3. รัน checkDatabaseReady เพื่อเพิ่ม User_Registration แบบ additive และตรวจหัวตาราง ไม่ต้องรัน setupInitialLoginAccounts ซ้ำ (เป็นการตั้งรหัสผ่านบัญชีเดิม)
4. ตั้ง Script Properties PRIVACY_CONTROLLER = สำนักงานเกษตรจังหวัด / กรมส่งเสริมการเกษตร (ระบุจังหวัดผู้รับผิดชอบให้ชัด), PRIVACY_CONTACT = ช่องทางติดต่อเรื่อง PDPA ที่หน่วยงานยืนยัน, PRIVACY_RETENTION = ระยะเก็บและวิธีลบตามนโยบายจริง ขาดค่าใดระบบปิดรับสมัคร ผู้ใช้ยังไม่ได้ให้ช่องทางติดต่อ/ระยะเก็บ จึงห้ามสมมติค่าแล้วเปิดรับสมัคร
5. ตรวจ privacy.html กับเจ้าหน้าที่ผู้รับผิดชอบ ตรวจฐานกฎหมาย ม.19/22/23/24(4), สิทธิม.30–36, มาตรการม.37, ผู้ประมวลผลม.40, และการส่งข้อมูลผ่านบริการคลาวด์ม.28–29 ตามข้อเท็จจริง ไม่อ้างว่ามี checkbox แล้วครบ PDPA โดยอัตโนมัติ
6. Deploy Apps Script เวอร์ชันใหม่บน deployment เดิมเพื่อคง URL /exec จากนั้นนำ Frontend รุ่นนี้ขึ้น GitHub main เมื่อ backend พร้อม การอัปโหลด main จะ deploy หน้าเว็บอัตโนมัติ
7. ทดสอบในสำเนาฐานก่อน: สมัคร → pending Login ไม่ผ่าน → ผู้ดูแลในจังหวัดอนุมัติ → Login ได้ → เห็นอำเภอ/จังหวัดตนเอง → บันทึกพร้อมภาพจริง → ภาพอยู่ใต้ HS ที่ยืนยัน → ผู้ไม่มีสิทธิ์อ่านภาพไม่ได้

## ข้อจำกัดและสถานะส่งมอบ
โค้ดล่าสุดทดสอบอัตโนมัติ125รายการผ่าน Backend รุ่น2.2 เคยติดตั้งและเผยแพร่บน Apps Script เดิมแล้ว ส่วนการปรับ UI PDPA วันที่18ตุลาคม2569 ยังไม่ได้เผยแพร่ขึ้น GitHub Pages ยังไม่ได้ทดสอบลงทะเบียน/อนุมัติ/รูปภาพแบบครบวงจรกับ Google จริง และยังปิดรับสมัครเพราะขาดช่องทางติดต่อและระยะเก็บข้อมูล อ่าน docs/PDPA-UI-UPDATE-TH.md เพิ่มเติม

ป้องกันสมัครถี่5ครั้ง/นาทีแบบ best effort และจำกัดจำนวนบัญชี/แถว200เริ่มต้น ปรับ REGISTRATION_MAX_ACCOUNTS ได้1–500 โดยยังติดเพดานพื้นที่ScriptProperties400KBพร้อมreserve8KB นี่ไม่ใช่ฐานบัญชีระดับประเทศปริมาณสูง ถ้าขยายจำนวนมากควรย้ายไป identity provider/ฐานข้อมูลที่เหมาะสม

Admin/Super Admin คงเครื่องมือจัดการเดิม ไม่เพิ่มคำสั่งล้างฐานหรือ permanent delete ใหม่
