# ปรับหน้าลงทะเบียนและประกาศ PDPA — 18 ตุลาคม 2569

ใช้โครงสร้างตามตัวอย่าง: หัวสีเขียว เนื้อหาเลื่อนได้ รายการเลขไทย ช่องรับทราบที่ไม่เลือกไว้ล่วงหน้า และปุ่มยกเลิก/ยืนยัน แบ่งกรอกข้อมูลกับอ่านประกาศเป็นสองขั้นตอน รองรับแป้นพิมพ์และหน้าจอเล็ก

## เหตุผลที่ปรับถ้อยคำ
สองวัตถุประสงค์ที่เสนอเป็นงานจำเป็นของบัญชีและความปลอดภัย จึงใช้ชื่อ “เอกสารรับทราบการใช้ข้อมูลส่วนบุคคล” และปุ่ม “ยกเลิกการลงทะเบียน” ให้ตรงกับสิ่งที่ระบบบันทึกจริง ไม่เปลี่ยนการรับทราบให้เป็นความยินยอมครอบคลุมทั้งหมด หากหน่วยงานเลือกใช้ฐานความยินยอมสำหรับกิจกรรมเพิ่มเติม ต้องแยกวัตถุประสงค์ ทางเลือก และช่องทางถอนต่างหาก

การใช้ฐานภารกิจสาธารณะต้องให้หน่วยงานตรวจสอบอำนาจหน้าที่ที่รองรับ ไม่ถือว่าการเป็นหน่วยงานรัฐทำให้ใช้ฐานนี้ได้ทุกกิจกรรม

## ไฟล์แก้ไข
registration-ui.js, registration.css, privacy.html และชุดทดสอบ tests/registration-consent.test.js, tests/registration-ui.test.js
ตัวอย่างที่อ่านได้โดยไม่กรอกบัญชี: docs/consent-preview.html
ไม่แก้ schema หรือสิทธิ์เดิมของฐานข้อมูล การรับทราบยังบันทึก privacy_version และ privacy_acknowledged_at ที่เซิร์ฟเวอร์ ไม่มีการเก็บรหัสผ่านในเบราว์เซอร์หรือ Sheet

## การเชื่อมต่อ
ใช้ Apps Script ชุด apps-script/ หรือไฟล์รวม docs/AppsScript-v22-All.gs อย่างใดอย่างหนึ่ง ห้ามใส่ซ้ำทั้งสองแบบ ตั้ง Script Properties: PRIVACY_CONTROLLER, PRIVACY_CONTACT, PRIVACY_RETENTION โดยใช้ข้อมูลที่หน่วยงานรับรอง จากนั้นเผยแพร่เวอร์ชันใหม่ของ deployment เดิม ตรวจ getRegistrationPolicy ให้ configured=true จึงทดสอบคำขอและการอนุมัติในพื้นที่ทดสอบ

ปัจจุบันมีชื่อผู้ควบคุมข้อมูลแล้ว แต่ยังขาดช่องทางติดต่อและระยะเก็บรักษา โค้ดจึงยังไม่เปิดรับคำขอจริง ไม่สมมติข้อมูลเหล่านี้แทนหน่วยงาน Frontend ใหม่ยังไม่ถูกเผยแพร่บน GitHub Pages ส่วน Apps Script รุ่น2.2.1 ได้ติดตั้งและเผยแพร่เป็น deployment เวอร์ชัน3 วันที่18ตุลาคม2569 เวลา06:50 ใช้ URL และสิทธิ์เดิม ประกาศรุ่น2026-10-v2 พร้อมฟังก์ชัน checkRegistrationPolicyReady ซึ่งตรวจสำเร็จบน Google

## ตรวจสอบ
ชุดทดสอบ 125 รายการผ่าน รวมกรณียกเลิกไม่เรียก register, ช่องรับทราบไม่เลือกอัตโนมัติ, ไม่มีนโยบายห้ามส่ง และกดซ้ำไม่สร้างคำขอซ้ำ
