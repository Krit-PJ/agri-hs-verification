## ทำไมยังต้องมี API
APIเป็นปลายทางตรวจบัญชีและอ่าน/บันทึกฐานกลาง ไม่ใช่ข้อมูลที่ผู้ดูแลต้องกรอกทุกครั้ง จึงกำหนดใน site-config.js ช่องapiEndpointก่อนเผยแพร่ และแสดงค่าหลัง LoginเฉพาะSuper Admin หน้าLoginไม่มีช่องURLแล้ว ถ้าค่าconfigว่างและไม่มีค่าที่เคยบันทึก ระบบแจ้งให้ผู้ติดตั้งกำหนดค่าโดยไม่จำลองLogin

## ทีมผู้พัฒนาและที่ปรึกษา
ทุกคนดูข้อมูลได้ ผู้ดูแลที่Loginแล้วเปิดเมนูทีมเพื่อเพิ่มหรือแก้ไข3ช่อง ชื่อ-สกุล ตำแหน่ง สังกัด กดบันทึกเพื่อจัดเก็บกลาง ข้อมูลผู้พัฒนาเริ่มต้นตามที่ผู้ใช้ระบุ ตำแหน่งเริ่มต้นใช้คำว่าผู้พัฒนาระบบ สามารถแก้เป็นตำแหน่งจริงหลังLogin ไม่เพิ่มรายชื่อที่ปรึกษาที่ไม่ได้รับข้อมูล
รองรับ20คนและตรวจขนาดข้อมูลเพื่อไม่เกินScript Properties มีrevisionป้องกันผู้ดูแลสองคนเขียนทับกัน ต้องเปิดหน้าทีมใหม่หากพบข้อมูลเปลี่ยนแปลง

## เชื่อมต่อ
1. นำ Apps Scriptทั้งหมดรวม TeamService.gsขึ้นโครงการเดิมและdeployเวอร์ชันใหม่
2. ตั้งบัญชีตาม AUTH_SETUP_TH.md หากยังไม่ตั้ง
3. ใส่URL /execในsite-config.js ไม่ใส่username/passwordในไฟล์นี้
4. เผยแพร่ไฟล์เว็บ เปิดหน้าLoginแล้วใส่เพียงชื่อผู้ใช้และรหัสผ่าน
5. Admin/Super Adminแก้รายชื่อทีมผ่านหน้าทีม ข้อมูลร่วมกันทุกอุปกรณ์

ยังไม่ได้deployหรือทดสอบGoogleจริง โหมดตัวอย่างแสดงรายชื่อเริ่มต้นและล็อกการแก้ไขจนLoginจริง ส่วนฐานHS ฟอร์มตรวจ รูปภาพ และรายงานยังคงเดิม งานA1ยังไม่รวมในรุ่นนี้
