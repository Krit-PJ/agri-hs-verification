# Design System — HS Verification จังหวัดกำแพงเพชร v1.3

## แนวคิดและขอบเขตการอ้างอิง
ออกแบบสำหรับหน่วยงานเกษตร โดยใช้แนวคิดสถาปัตยกรรมข้อมูลของ Open Government Data of Thailand: ค้นหาชุดข้อมูล แยกหมวด ตัวกรอง และแสดงที่มาชัดเจน ไม่ได้คัดลอกแบรนด์หรืออ้างว่าตรวจ CSS ของเว็บไซต์ต้นแบบครบถ้วน หน้างานเน้นแผนที่ก่อน การเลือกจุดและยืนยันข้อมูล การตรวจสอบที่มาหลักฐาน และสถานะที่สื่อสารด้วยข้อความร่วมกับสี

อ้างอิง: [data.go.th ชุดข้อมูล](https://data.go.th/dataset/), [WCAG 2.2](https://www.w3.org/TR/WCAG22/), [เกณฑ์ contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [ขนาดเป้าหมาย](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html), [focus ไม่ถูกบดบัง](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)

## 1. Typography
ใช้ Noto Sans Thai สำหรับหัวข้อและปุ่ม ใช้ Sarabun สำหรับเนื้อหาและช่องกรอก โดยบรรจุไฟล์ฟอนต์จริงใน assets/fonts พร้อมใบอนุญาต SIL OFL และ font-display:swap เพื่อให้หน้าเว็บแสดงสม่ำเสมอโดยไม่ต้องเชื่อมบริการฟอนต์ภายนอก

| ระดับ | ขนาด desktop | ขนาดมือถือ | น้ำหนัก | line-height |
|---|---|---|---|---|
| H1 | 32–44px | 30px | 750 | 1.32 |
| H2 | 24–30px | 24px | 700 | 1.4 |
| H3 | 20px | 20px | 650 | 1.45 |
| H4 | 18px | เท่ากัน | 700 | 1.45 |
| H5 | 16px | เท่ากัน | 700 | 1.45 |
| H6 | 15px | เท่ากัน | 700 | 1.45 |
| Body / ช่องกรอก | 16px | เท่ากัน | 400 | 1.65 |
| Label | 14px | เท่ากัน | 550 | 1.6 |
| Hint / metadata | 13px | เท่ากัน | 400 | 1.6 |

หัวข้อการ์ดรายการ HS ใช้16px เพื่อให้สแกนข้อมูลจำนวนมากง่าย ส่วนรหัสHSใช้12pxและตัดแสดงเฉพาะในรายการ โดยเปิดดูรหัสเต็มในฟอร์มได้

ขนาด rem อ้างอิง root 16px แต่ไม่ล็อก root เพื่อให้การปรับตัวอักษรของผู้ใช้มีผล ใช้ลำดับหัวข้อตามความหมาย ห้ามเลือก H6 เพราะอยากได้ตัวเล็ก ใช้ tabular-nums สำหรับข้อมูลสถิติ เลี่ยง letter-spacing มากในภาษาไทย

## 3. Grid, spacing และ theme
ใช้พื้นสว่างและ white space ไม่มี theme มืดในรุ่นนี้ ระยะฐาน 4px: 4/8/12/16/20/24/32/48px ความกว้างเนื้อหาสูงสุด 1440px ขอบหน้า desktop 42px หรือตาม viewport มือถือ 16px แผนที่และรายการแบ่งคอลัมน์ desktop; ต่ำกว่า 800px วางเรียงแนวตั้ง แสดงรายการแบบเลื่อนได้และยังมีปุ่มนำทางแยก

## 4. Buttons, cards, tables
ปุ่มหลักพื้น primary ข้อความขาว ขนาดสัมผัสอย่างน้อย 48×48px padding 11px 18px radius 10px hover primary-hover ปุ่มรองพื้นขาว เส้นและข้อความ primary hover primary-soft หนึ่งกลุ่มงานควรมี primary เด่นเพียงหนึ่งปุ่ม ปุ่ม destructive ใช้ error และข้อความชัด ไม่มี icon เดี่ยวโดยไม่มีชื่อสำหรับเครื่องอ่านหน้าจอ

การ์ด radius16px padding24px desktop/18px mobile border1px border shadow 0 4px 18px rgba(23,45,36,.045) ใช้เงาเบาเพื่อสื่อโครงสร้าง ไม่ทำให้ทุกองค์ประกอบดูเป็นปุ่ม ตารางหัวพื้น #EEF4EF ตัวเข้ม เส้นแนวนอน ข้อมูลตัวเลขชิดขวาเมื่อเหมาะสม มีหัวตารางและ caption หรือชื่อส่วนกำกับ บนมือถือให้เลื่อนในกรอบตาราง ไม่ทำให้ทั้งหน้าเลื่อนแนวนอน

## 5. Iconography
ใช้ SVG line icons 24×24 viewBox, stroke-width1.8 หรือ 2, rounded linecap/join และ currentColor รูปแบบเดียวกันทั้งระบบ เช่น map-pin, camera, image, leaf, layers, check, alert, upload ไม่ใช้ emoji เป็นเครื่องหมายสถานะหลัก ไอคอนประกอบข้อความใส่ aria-hidden=true ปุ่ม icon เดี่ยวต้องมี aria-label ความหมายไม่พึ่งสีหรือรูปเพียงอย่างเดียว

## 6. Form และ progressive disclosure
เส้นทางหลัก: เลือก HS → ยืนยันผล → ถ่าย/แนบภาพ → ยืนยันส่ง ไม่พิมพ์ HS ID วันเวลาและพื้นที่ซ้ำ แสดงข้อมูล auto-fill เป็นส่วนอ่านอย่างเดียว พร้อมปุ่มแก้ไขเฉพาะข้อมูลภาคสนามที่มีสิทธิ์

ตัวกรองเริ่มจากปีล่าสุด พื้นที่ และสถานะ; ตัวกรองเสริมอยู่ในรายละเอียดเพิ่มเติมเมื่อพื้นที่จอจำกัด ให้มองเห็นสรุปตัวกรองที่ใช้อยู่ จำนวนผลลัพธ์ และปุ่มล้าง อำเภอ→ตำบล→หมู่บ้านล้างค่าลูกเมื่อเปลี่ยนค่าพ่อ ห้ามให้ผู้ใช้เลือกค่าที่ไม่มีในผลลัพธ์ คลิก HS แล้วเติมค่าที่เกี่ยวข้อง พร้อมข้อความว่ากำลังเลือกจุดใด

บุคคลใช้ตัวเลือก นักวิชาการส่งเสริมการเกษตร, กำนัน, ผู้ใหญ่บ้าน, ผู้ช่วยผู้ใหญ่บ้าน, อกม., อื่นๆ โปรดระบุ เปิดช่องระบุเฉพาะเลือกอื่นๆ และจำค่าใน profile ตามสิทธิ์ ประเภทบุคคลไม่ใช่บทบาทสิทธิ์ Admin/Super Admin

เมื่อพื้นที่จริงตรงกับต้นทาง ให้ยืนยันครั้งเดียว เมื่อไม่ตรงจึงเปิดช่องพื้นที่/พืชจริง กรณีพบไฟถามสถานะไฟเพิ่มเติม กรณีตรวจไม่ได้แสดงเหตุผล หลีกเลี่ยงบังคับหมายเหตุทั่วไปทุกครั้ง ข้อผิดพลาดแสดงติดช่อง พร้อมคำอธิบายที่แก้ได้ และไม่ล้างข้อมูลที่กรอกแล้ว

หลักฐานภาพแสดงที่มาพิกัด เวลาถ่าย/เขตเวลา ระยะถึง HS และข้อจำกัดแยกแต่ละภาพ ภาพนำเข้าไม่ใช้ GPS ปัจจุบันแทนจุดถ่ายเดิม ไม่เปิดช่องพิมพ์พิกัดเป็นค่าเริ่มต้น ยืนยันเพิ่มเติมเมื่อข้อมูลขาดหรือขัดแย้ง

## 7. Accessibility และเงื่อนไขก่อนประกาศ WCAG AA
เป้าหมาย WCAG2.2 AA: ข้อความปกติ contrast≥4.5:1 ข้อความใหญ่≥3:1 ขอบควบคุมและสถานะจำเป็น≥3:1 ใช้เป้าหมายสัมผัส48px แม้ SC2.5.8 AA กำหนดขั้นต่ำ24 CSS px พร้อมข้อยกเว้น วง focus3px และขอบขาวคั่น ไม่ถูกแถบ sticky บัง ปิด animation เมื่อ prefers-reduced-motion

tests/design-system.test.mjs ตรวจคู่สี token สำคัญโดยคำนวณ relative luminance จริง ต้องทดสอบ keyboard, dialog focus trap/return, screen reader, zoom200%/400%, จอ320px, กลางแจ้งและอุปกรณ์จริงเพิ่มเติมก่อนกล่าวว่าได้รับการรับรอง AA การทดสอบ token ไม่ใช่การรับรองทั้งเว็บไซต์ SC2.4.13 Focus Appearance เป็น AAA ไม่อ้างเป็นข้อบังคับ AA Placeholder ไม่แทน label; แม้ disabled controls ได้รับข้อยกเว้นด้าน contrast ยังออกแบบให้อ่านได้

## 8. ส่งต่อ Figma/CSS
ไฟล์ design-tokens.css ใช้ CSS variables ได้ทันที โดยโหลดก่อน styles.css ไฟล์ design-tokens.json ใช้โครงสร้าง Design Tokens Community Group: $type/$value สี sRGB และ dimension px สำหรับแปลงผ่านเครื่องมือจัดการ token เข้าสู่ Figma Variables ต้องเลือก plugin/ตัวแปลงและตรวจ alias ไม่ใช่ไฟล์ native Figma ที่นำเข้าได้ทุกกรณี

ตั้ง Figma Collections: Color (semantic), Space, Radius, Type ตั้ง components variant: default/hover/focus/disabled/error, density field48, card default/selected, evidence consistent/review/insufficient ให้ชื่อ layer ตามหน้าที่ เช่น Evidence/Metadata/Source ไม่ใช้ชื่อสีแทน semantic

## Checklist ส่งมอบ
- แผนที่ก่อนส่วนค้นหา; ที่มาข้อมูลและโหมดตัวอย่าง/ระบบกลางเห็นชัด
- ทุกฟอร์มมี label และข้อความสถานะ; แจ้งข้อยกเว้นใกล้การกระทำ
- สีข้อความทุกสถานะที่กำหนดใน token ผ่าน test contrast ที่เกี่ยวข้อง
- ทดสอบ responsive และปุ่มที่เกี่ยวข้องกับสิทธิ์ด้วยบัญชีจริงก่อนใช้งานกลาง
