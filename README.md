# รุ่นล่าสุด v1.4 — ชื่อระบบ เมนู และทีมผู้พัฒนา

เปลี่ยนชื่อเป็นระบบตรวจสอบจุดความร้อน พร้อมข้อความพื้นที่การเกษตรในจังหวัดกำแพงเพชรและเครดิตผู้พัฒนาตามที่ระบุ จัดเมนูสรุปผลการตรวจสอบ → ตรวจสอบจุดความร้อน → ผู้ดูแลระบบ → ทีมผู้พัฒนาและที่ปรึกษา พร้อมลิงก์แผนที่ความเสี่ยงฉบับเผยแพร่ และส่วนท้าย copyright

หน้า Login เหลือชื่อผู้ใช้และรหัสผ่านเท่านั้น **ผู้ติดตั้งกำหนด Apps Script /exec URL หนึ่งครั้งใน site-config.js ช่อง apiEndpoint ก่อนเผยแพร่** ค่า URL ที่เคยตั้งในอุปกรณ์ยังใช้ได้เมื่อ config ว่าง ไม่มีรหัสผ่านอยู่ในไฟล์นี้ ปลายทางแสดงให้ Super Admin ดูได้หลัง Login ระบบจำเป็นต้องทราบปลายทางก่อนส่งชื่อผู้ใช้ไปตรวจสอบ จึงไม่สามารถเริ่ม Login กับฐานจริงได้ถ้ายังไม่ตั้งค่าปลายทางเลย

หน้าทีมเปิดอ่านได้ทุกคน ผู้ดูแลที่เข้าสู่ระบบเพิ่ม/แก้ไขชื่อ ตำแหน่ง สังกัดได้ ข้อมูลเก็บกลางใน Script Properties ผ่าน TeamService.gs ตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์และป้องกันการเขียนทับการแก้ไขของคนอื่น ต้องนำ TeamService.gs และ Code.gs ฉบับใหม่ขึ้น Apps Script และ deploy รุ่นใหม่

# รุ่นล่าสุด v1.3 — หน้าจอ Login และรายงาน PDF

- ฟอนต์หัวข้อ Noto Sans Thai / เนื้อหา Sarabun บรรจุไฟล์จริงใน assets/fonts พร้อมใบอนุญาต
- โลโก้ DOAE / กำแพงเพชร พื้นหลังโปร่งใสใน assets แสดงหน้าเว็บและรายงาน
- Admin/Super Admin ต้องเข้าสู่ระบบผ่าน Apps Script ก่อน ไม่มีการตรวจรหัสผ่านในไฟล์เว็บ
- Admin เห็น QA / ส่งออก / รายงาน ส่วน Google Workspace เซิร์ฟเวอร์ และนำเข้า HS แสดงเฉพาะ Super Admin
- สรุปผล → เลือกอำเภอ/ทั้งจังหวัดและปี → พิมพ์รายงาน / บันทึก PDF → พิมพ์ → เลือก Save as PDF จัดหน้า A4 แนวนอน รองรับ Chrome/Edge; เบราว์เซอร์ในแอปบางตัวอาจไม่แสดงหน้าต่างพิมพ์ ให้เปิดเว็บใน Chrome/Edge

**ต้องตั้งค่าบัญชีก่อน Login จริง:** ใช้ชื่อผู้ใช้ `620000` (Admin) และ `Krit` (Super Admin) กรอกรหัสผ่านที่ผู้ใช้กำหนดใน Script Properties แล้วรัน `setupRequestedLoginAccounts()` ดู [คู่มือตั้งค่า Login](docs/AUTH_SETUP_TH.md) ไม่เก็บรหัสผ่านจริงในไฟล์เว็บหรือคู่มือ

ยังไม่ได้ deploy Google/GitHub หรือสร้างบัญชีบน Google จริง โค้ดพร้อมตั้งค่าและตรวจสอบด้วยบัญชีจริงต่อได้ หน้าเว็บในเครื่องแสดงตัวอย่างข้อมูลได้ แต่พื้นที่ผู้ดูแลต้องเชื่อม API ที่ตั้งค่าบัญชีแล้ว

# HS Verification v1.2 — อัปเดตประเภทบุคคลและ Design System

เพิ่มประเภทผู้ลงพื้นที่ 6 กลุ่ม แยกจากสิทธิ์ inspector/admin/super_admin พร้อมช่องระบุเมื่อเลือกอื่นๆ และจำค่าประเภทบนอุปกรณ์/โปรไฟล์เมื่อบันทึกด้วยบัญชีตนเอง

รุ่น 2.2 อ่าน EXIF ก่อนย่อ JPEG ไม่เกิน 1,000,000 ไบต์ ด้านยาวไม่เกิน 1920px แล้วส่งภาพย่อ เก็บ SHA-256 ต้นฉบับและภาพย่อแยกกัน ข้อมูล EXIF ต้นฉบับที่ไคลเอนต์ส่งมาไม่ใช่ metadata ที่เซิร์ฟเวอร์พิสูจน์จากต้นฉบับ จึงระบุแหล่งที่มาและคำเตือนชัดเจน ภาพเดิมอ่านได้ตามเพดานเดิม 5 MiB ภาพ HEIC ยังไม่รองรับ

ใช้สี forest green, typography และระยะห่างจาก design-tokens.css/JSON คู่มือพร้อมใช้กับ CSS และการแปลงเข้า Figma: [Design System ภาษาไทย](docs/DESIGN_SYSTEM_TH.md) การทดสอบคอนทราสต์ไม่ใช่การรับรอง WCAG AA ทั้งเว็บไซต์

**อัปเกรดฐานเดิม:** สำรอง Google Sheet แล้วนำไฟล์ Apps Script ทั้งหมดรวม Evidence.gs ไปแทน จากนั้นเรียก migrateSchemaV12() ก่อนเผยแพร่เวอร์ชันใหม่ ดู apps-script/README.md ไม่ต้องนำเข้า CSV ทับข้อมูลเดิม

การยืนยันส่งรายงานกับความครบถ้วนหลักฐานเป็นคนละสถานะ ยังไม่มีรัศมีความคลาดเคลื่อนจากแหล่งดาวเทียม จึงรายงานระยะเพื่อสอบทวนและระบุว่าหลักฐานไม่พอสำหรับรับรองอัตโนมัติ EXIF อาจถูกแก้ไขได้

ยังไม่ได้ deploy Google/GitHub จริง ต้องเชื่อมบัญชีและทดสอบสิทธิ์/Drive/Apps Script หลังตั้งค่า โหมดตัวอย่างไม่เก็บไฟล์ภาพไว้บนระบบกลาง

# HS Verification Database Module v1.1 — จังหวัดกำแพงเพชร

ระบบย่อยตรวจผล Hotspot ภาคสนาม เชื่อมระบบ Agri-Risk Map Burning ที่ `risk/index.html` และมีลิงก์กลับหน้า Verification ในสำเนาระบบเดิม ไม่มีการแก้ไฟล์ต้นฉบับหรือ sources

## เริ่มทดลอง
เปิด terminal ในโฟลเดอร์นี้ เรียก `python -m http.server 8080` แล้วเปิด `http://localhost:8080` (อย่าเปิดผ่าน file:// เพราะต้องโหลด JSON) หน้าเว็บใช้โหมดทดลองเมื่อยังไม่ตั้ง endpoint ข้อมูล HS จริง 593 จุดจากชุดข้อมูลเดิมแต่ผลตรวจทดลองเก็บเฉพาะเครื่อง ไม่ใช่ฐาน Google และไม่ใช่ผลตรวจจริง

## โครงสร้าง
- `index.html`, `styles.css`, `app.js`: แผนที่ ฟอร์ม รายงาน Admin
- `apps-script/`: API และ manifest สำหรับ Google Apps Script
- `templates/`: CSV headers และ schema สำหรับ Google Sheets
- `data/risk-datasets.json`, `data-source.js`, `risk-data-bridge.js`: อ่าน HS ชุดเดียวกับ risk map และเลือกปีชุดล่าสุด
- `data/hs-base.json`, `HS_Base_seed.csv`, `provenance.json`: ชุด HS seed พร้อมที่มา
- `risk/`: สำเนาเว็บประเมินความเสี่ยงเดิม พร้อมเมนูเชื่อมกลับ
- `docs/`: คู่มือ UI การติดตั้งและใช้งาน
- `.github/workflows/pages.yml`: เผยแพร่ GitHub Pages เมื่อผู้ดูแลสั่ง workflow เท่านั้น

## เงื่อนไขฐานข้อมูล
Province = กำแพงเพชร, LandType = พื้นที่เกษตร, PlantType = นาข้าว / อ้อย / เกษตรอื่นๆ / อื่นๆ ยอมรับรูปเขียนมีช่องว่างแล้ว normalize

ระบบเดิมระบุ `hsPlant2026` เป็น Pivot สรุปยอด ข้อมูลรายจุดอยู่ `hsAll` ใน workbook เดียวกัน seed นี้ผ่านการเทียบยอด 593 จุด (นาข้าว 448, อ้อย 84, เกษตรอื่นๆ 59, อื่นๆ 2) ช่วง 2025-10-02 ถึง 2026-08-26 ไม่ใช่ข้อมูลปัจจุบันแบบ realtime ห้ามสรุปว่าครบปี 2569

ค่า year_be เป็นปีปฏิทินของวัน HS (มีทั้ง 2568/2569) ต่างจาก dataset_year_be/season_be 2569 ในระบบความเสี่ยงเดิม หมู่บ้านที่ไม่มีค่าจะคงว่าง ไม่มีการเดา ID แปลง เนื่องจากข้อมูลต้นทางไม่มี ID แปลงที่ยืนยันได้
